# ADR-001: Переход на улучшенную архитектуру API по результатам MDD-анализа

**Дата:** 30.05.2026
**Статус:** Принято

## Контекст
В рамках развития системы предиктивного обслуживания автомоек "NDA" предложено архитектурное изменение, направленное на снижение времени отклика API. Проведено A/B-тестирование: существующая и улучшенная версии системы развернуты параллельно, собрано по 500 000 наблюдений времени отклика на каждую.

## Данные
- Существующая система: среднее время отклика 3.50 сек, стандартное отклонение 0.40 сек.
- Улучшенная система: среднее время отклика 2.00 сек, стандартное отклонение 0.40 сек.
- Разница средних: 1.50 сек (улучшение на 42.9%).

Визуализация распределений сохранена в `docs/latency_comparison.png`. Улучшенная система демонстрирует явный сдвиг распределения влево (меньшее время отклика) при той же стабильности.

## Гипотезы
- H0: Среднее время отклика существующей и улучшенной системы одинаково. Разница в выборочных средних объясняется случайностью.
- H1: Среднее время отклика улучшенной системы статистически значимо ниже.

## Метод
Двусторонний t-тест для независимых выборок. Размер выборок - по 500 000 наблюдений, распределения близки к нормальным согласно центральной предельной теореме. Уровень значимости = 0.05.

## Решение
- t-статистика: 1875.08
- p-value: 0.000000 (значительно меньше 0.05)

Нулевая гипотеза H0 **отклоняется**. Улучшенная система демонстрирует статистически значимое снижение времени отклика на 1.50 секунды (улучшение на 42.9% относительно существующей).

**Итоговое решение:** Переход на улучшенную архитектуру API.

## Последствия
- Новая версия API переводится в Production через MLflow Registry.
- Старая версия перемещается в Archived.
- Мониторинг времени отклика (SLI-3, SLO < 200 мс) продолжается для валидации решения на реальной нагрузке.
- При падении производительности ниже SLO проводится повторный MDD-анализ и новое ADR.
