# SLI/SLO: Система предиктивного обслуживания автомоек

## Технический уровень

### SLI-1: Доступность MLflow Tracking Server
- **Что измеряем:** Доля успешных HTTP-запросов к MLflow (код 200).
- **Как измеряем:** Docker healthcheck (статус контейнера `healthy` в `docker ps`).
- **SLO:** Контейнер в статусе `Up (healthy)`.
- **Критический порог:** Контейнер остановлен или `unhealthy`.

### SLI-2: Доступность FastAPI
- **Что измеряем:** Доля успешных ответов на `/health` (код 200).
- **Как измеряем:** Docker healthcheck, встроенная проверка.
- **SLO:** Контейнер в статусе `Up (healthy)`.
- **Критический порог:** Контейнер `unhealthy` или остановлен.

### SLI-3: Загрузка CPU (системная метрика)
- **Что измеряем:** Средняя загрузка CPU хоста за 5 минут.
- **Как измеряем:** Prometheus + Node Exporter.
- **SLO:** < 70% утилизации.
- **Критический порог:** > 90% - риск деградации всех сервисов.

### SLI-4: Использование памяти (системная метрика)
- **Что измеряем:** Использование оперативной памяти хоста.
- **Как измеряем:** Prometheus + Node Exporter.
- **SLO:** < 80% от общего объема.
- **Критический порог:** > 90% - риск OOM-kill контейнеров.

---

## Модельный уровень

### SLI-5: Recall (полнота предсказаний поломок)
- **Что измеряем:** Доля реальных поломок, которые модель предсказала, на тестовой выборке.
- **Как измеряем:** Расчет в DAG Airflow при каждом переобучении (офлайн-метрика).
- **SLO:** ≥ 80%.
- **Критический порог:** < 60% - модель не проходит в Production.

### SLI-6: Precision (точность предсказаний поломок)
- **Что измеряем:** Доля предсказанных поломок, которые реально произошли, на тестовой выборке.
- **Как измеряем:** Расчет в DAG Airflow при переобучении.
- **SLO:** ≥ 60%.
- **Критический порог:** < 50% - слишком много ложных тревог.

### SLI-7: Количество пропущенных поломок (False Negative)
- **Что измеряем:** Абсолютное число поломок в тестовой выборке, которые модель НЕ предсказала.
- **Как измеряем:** Confusion matrix в DAG Airflow.
- **SLO:** ≤ 3 пропущенных поломки.
- **Критический порог:** > 5 - модель не готова к использованию.

---

## Бизнес-уровень

### SLI-8: Время простоя боксов
- **Что измеряем:** Доля времени, которое боксы проводят в ремонте, от общего времени.
- **Как измеряем:** Данные из ERP заказчика (в учебном проекте - эмулируется через синтетические данные).
- **SLO:** < 5% времени простоя.
- **Критический порог:** > 8% - система не достигает бизнес-цели.
